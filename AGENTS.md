# MSB Nanotech — Agent Design & Engineering Orchestration

## Non-negotiable
Do not deliver generic template UI or jump straight to coding. Treat the skills requested by the owner as a coordinated multidisciplinary team. **Actually discover, read and invoke relevant installed skill instructions and tools** before implementation. A skill name in this document is not evidence it was used. If a skill is not installed/available, state that limitation and use the strongest available equivalent without claiming invocation.

## Project brief
Create an original, distinctive, premium digital experience for MSB Nanotech Solutions—not a generic startup template. Maintain factual content, brand/logo, and functional navigation. The visual concept, typography, composition, imagery, spatial elements and interaction model must be purposefully art-directed. Make the site memorable and coherent, not noisy. The current project is a static multi-page site; do not migrate frameworks or introduce complex infrastructure without evidence that it is necessary.

## Mandatory orchestration workflow
1. **Audit / discovery:** inspect every page, assets, styles, scripts, links, existing brand material, content, and responsive behavior. Identify deficiencies and user journeys. Never fabricate institutional facts, metrics, campuses, testimonials, events, photos or credentials.
2. **Skill discovery:** identify the actual installed skill files/instructions and relevant tool availability in the current environment. Read them, not merely name them. Select specialists based on task. Explicitly record skill name, instruction path, and what decision/change it informed in a concise internal/work summary. Use tool-native workflows when available.
3. **Research:** study real design references and interactions where browsing tools are available. Use targeted references—not copying. Build a visual direction, moodboard/reference rationale, type scale, color system, spacing/grid, responsive composition, motion principles, imagery strategy and navigation model before coding.
4. **Design exploration:** produce at least 2 materially distinct design directions (not superficial color variants), compare their strengths, and choose the most compelling coherent direction. Use visual assets/media generation when genuinely useful. Never use placeholder gradients, fake dashboard statistics, random blobs, decorative clutter, stock photos that don't fit, or default component-library styling as a substitute for design.
5. **UX:** define user journeys for students, colleges/organizers and visitors; navigation and information hierarchy; content strategy; discoverability; error/empty states; interaction affordances; keyboard and touch behavior. Keep UX writing concise and authentic.
6. **Art direction:** original signature composition, considered typography, intentional whitespace, credible editorial rhythm, high-quality imagery/visual storytelling, brand identity continuity, color contrast, and optical alignment. Avoid overused glassmorphism, neon gradients, excessive cards, pill-everything, generic centered hero templates, artificial AI copy and indiscriminate animation.
7. **Implementation:** preserve current site architecture unless a justified change is needed. Use semantic HTML, reusable components/styles, maintainable state, modern CSS, progressively enhanced interactions, robust responsive layout and minimal dependencies. Avoid framework migration merely to appear modern. Use TypeScript/React/Next/Tailwind only when project constraints and task genuinely warrant them.
8. **Motion:** use GSAP/ScrollTrigger, Framer Motion, SVG, Three.js/R3F/Drei, WebGL/WebGPU, shaders, particles, parallax, cursor interactions, liquid motion, typography animation and 3D effects only when relevant and available. They are optional specialist instruments, not a checklist. One signature immersive feature should outperform dozens of gimmicks. Use physics-aware easing, interruptible motion, reduced-motion support, no motion-induced layout shift, and no heavy autoplay.
9. **Media production:** use Canva when connected for branded graphic assets, image layouts or creative assets where it materially helps. Use available video-generation tools (e.g. Runway/fal/other connected provider) to produce or refine actual short media when the concept calls for it. Create a brief/storyboard, aspect ratio, shot list, aesthetic and use; produce media, inspect it and use it only if it genuinely improves the experience. Never claim media tools were used if they were not connected/invoked. If unavailable, transparently explain and provide a ready-to-use production prompt; do not fake video with a placeholder.
10. **Performance & architecture:** ensure responsive images, lazy loading where appropriate, stable dimensions, asset sizing, efficient animation, code quality, no unnecessary dependencies, resilient loading/failure states, security, SEO metadata and semantic hierarchy. Do not sacrifice performance for effects.
11. **Accessibility:** semantic landmarks, logical heading hierarchy, accessible names, keyboard navigation, visible focus, color contrast, touch targets, reduced motion, captions/transcripts where needed, and screen-reader support. Audit form UX and states.
12. **QA:** do not declare success based only on code inspection. Run available lint/build/test checks, inspect the actual rendered website at desktop/tablet/mobile, test keyboard/touch navigation and key workflows, verify links and forms, inspect motion/reduced motion, test browser compatibility, audit accessibility and Lighthouse/Core Web Vitals if tools are available, and fix defects. Use screenshots/visual regression comparisons when available. If a QA tool is unavailable, state exactly what was not verified.
13. **Iteration:** critique the rendered output against the selected design direction. Run at least two real refinement cycles when tooling allows: critique, fix, re-render, compare. Check the whole page and all pages—not only the hero. Don't stop at the first implementation.
14. **Delivery:** summarize what was genuinely changed, tools/skills actually used (with evidence such as file paths, outputs or tool calls), tests/QA performed, known limitations and deployment state. No unverifiable claims.

## Design bar
The outcome must feel authored and art-directed, not generated from a common template. Make the site coherent, expressive, content-led, legible, responsive, performant and usable. Effects must support the content and brand. Real images, motion and interactive objects should have a purpose. Never invent real-world content.
